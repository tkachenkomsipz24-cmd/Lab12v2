## 2. Індивідуальне завдання (Варіант 2)

**Сценарій:** Запис у файл та вивантаження по мережі.  
Реалізувати класи `FileProcessor` та `NetworkClient`, а також узагальнений допоміжний клас `RetryHelper`.

* **Метод `FileProcessor.WriteToFile`:** Імітувати `IOException` перші 3 рази, потім успіх.
* **Метод `NetworkClient.UploadFile`:** Імітувати `HttpRequestException` перші 2 рази, потім успіх.
* **Клас `RetryHelper`:** Узагальнений метод `ExecuteWithRetry<T>` з експоненційною затримкою між повторами та делегатом `shouldRetry`.
* **Делегат `shouldRetry`:** Повторювати операції лише для `IOException` та `HttpRequestException`.

## 3. Структура проєкту

* `lab12v2/FileProcessor.cs` — клас, що імітує запис у файл із тимчасовими блокуваннями (`IOException`).
* `lab12v2/NetworkClient.cs` — клас, що імітує мережеві запити з тимчасовими таймаутами (`HttpRequestException`).

* `lab12v2/Program.cs` — головний файл із точкою входу `Main`, де тестується успішна обробка помилок та переривання для невідомих винятків.
* `.gitignore` — конфігураційний файл для виключення системних та тимчасових файлів .NET.

## 5. Висновок

Експоненційна затримка у патерні Retry забезпечує поступове збільшення часу очікування між спробами (як видно з консолі: 0,5с, потім 1с, потім 2с). Це дозволяє уникнути перевантаження ресурсів системи під час тимчасових збоїв. У цьому варіанті патерн успішно застосовано для вирішення проблем блокування файлу (`IOException`) та тимчасової недоступності мережі (`HttpRequestException`). Використання делегата `shouldRetry` дозволяє гнучко налаштовувати, які саме винятки варто обробляти повторно, роблячи код більш надійним.
